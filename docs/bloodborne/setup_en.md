## Required software

- **A Windows PC.** The launcher and the client are Windows-only.
- **Your own Bloodborne game files**: a PS4 dump of **`CUSA03173`** (Game of the Year Edition)
  at update **01.09**. No game files are distributed with this project, and no other release
  works — not the US standard edition `CUSA00900`, not the EU `CUSA00207`, and not a pre-modded
  repack, whose executable is usually already patched into something the client will refuse.
  Either install layout is fine: a merged dump already at 01.09, or a vanilla base with the
  update beside it in `CUSA03173-patch` / `CUSA03173-UPDATE`.
- **shadPS4 0.18.0**, the emulator the mod runs under. You do not have to configure it first:
  the launcher hands it the game folder on the command line. "shadPS4 game folder" means the
  folder *containing* `CUSA03173`, not the folder shadPS4 itself lives in.
- **The launcher package**, `BloodborneAPLauncher-win-x64.zip`, from the
  [releases page](https://github.com/4laric/bb-archipelago/releases). Unzip it anywhere.
- **The Bloodborne apworld**, `bloodborne.apworld`, from the same release. Only the person
  generating the seed needs it.
- **Cheat Engine is not needed.** Item delivery is native and the launcher does not open Cheat
  Engine at all. Do not install it unless your host explicitly asks you to run the client with
  `--delivery=ce-bridge`.

Take both files from the **same release**: the launcher refuses a seed generated by a different
apworld version, which is the check that keeps a silent version mismatch from looking like a bug
in the game.

## Making a yaml

Use the [options wizard](https://peliarch.ca/bb/wizard.html), which renders from this apworld's
own option surface and stamps the apworld version into the yaml's `description`. Or start from
`examples/central-yharnam-variety.yaml` in the repository.

The options worth deciding before you generate, because they change the size or the shape of the
seed and cannot be changed afterwards:

| Option | What it does |
|---|---|
| `goal` | Which of the three endings finishes the seed. Moon Presence, the default, additionally needs three of the four shuffled Third Umbilical Cords. |
| `include_dlc` | Adds The Old Hunters regions, checks, and progression items. |
| `include_dlc_gear` | Independent of the above: DLC weapons and attire in the pool even on a base-game route. |
| `one_time_enemy_checks` | Adds checks for reviewed non-respawning hunters and unique enemies. |
| `randomize_shops` | Shuffles which hunter badge unlocks each ordinary Bath stock group. |
| `alternate_hypogean_gaol_routes` | Permits nonstandard progression after the Blood Moon. Off by default. |

## Installing the apworld (host only)

Put `bloodborne.apworld` in your Archipelago installation's `custom_worlds` folder, or run

```
python tools/install_apworld.py --ap-dir <your Archipelago directory>
```

from a checkout of the repository, which installs `worlds/bloodborne` directly and works on
Windows and Linux alike.

## Installation procedure (about five minutes)

1. Run **BloodborneAPLauncher.exe**.
2. Fill in the four fields the launcher cannot guess: **shadPS4.exe**, the **AP seed file**
   (the whole `AP_<seed>.zip` is fine — the launcher finds your Bloodborne slot inside it), the
   **Archipelago server** address, and **your AP player name**, spelled exactly as your host
   spelled it. In a multiworld with more than one Bloodborne player, fill the player name in
   first: the launcher refuses to guess which slot is yours. Click **Save Setup**.
3. Click **Generate Launch Plan** once.
4. Click **Doctor**. Every line should read `PASS`. A `FAIL` prints a `->` remedy underneath it;
   follow that before going any further.
5. Click **Randomize & Launch**.

## Joining a MultiWorld game

The launcher starts the Archipelago client and the emulator together and connects to the server
you gave it, so there is nothing else to launch and no console command to type. Once you are in
the game, picking up a randomized item sends the check; items other players find for you arrive
in the game as native item grants, one at a time.

The one chokepoint worth knowing before you start: the **Hunter Chief Emblem** gates Cathedral
Ward, so an early seed can look empty until it turns up. Lamps are your only fast travel, and
the DLC is a gate rather than a side area — with `include_dlc` off, none of its checks exist.

## Troubleshooting

- **"unrecognized game build"**: the client refuses to deliver into a build it has not
  validated. Check the title id and the update version first; this is almost always a dump
  problem, not a client one.
- **Nothing is delivered, but the client says it is connected**: open the launcher's
  **Open Diagnostics** and look at the newest `sessions\<id>` folder.
- **Anything else**: [report it](https://peliarch.ca/bb/report.html), and attach the session
  folder — `client.log`, `delivery-diagnostics.jsonl`, `ledger.json`, and
  `rescue-diagnostics.json` are what a diagnosis is actually made from.

The current rough edges are listed in

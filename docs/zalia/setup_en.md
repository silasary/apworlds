# ZALiA Multiworld Setup Guide

## Requirements

Players need:

- ZALiA Client
- Clean USA Zelda II NES ROM, headered or headerless

The person generating the multiworld also needs:

- Archipelago 0.6.6 or newer
- `zalia.apworld` installed

ZALiA contains its own Archipelago client. No emulator connector or separate Archipelago text client is required.

## Install the APWorld

This is required on the machine that generates the multiworld; players connecting only through the standalone game do not need it.

1. Copy `zalia.apworld` into the Archipelago `custom_worlds` folder next to the launcher
2. Re/start the Archipelago Launcher
3. Generate Template Options
4. Put the Template yaml from /Players/Templates/ into the /Players/ folder
5. Generate a multiworld

Seeds generated by mismatching ZALiA APWorld versions are rejected by older/newer game clients.

## Install the Game

1. Extract the ZALiA Windows ZIP to any writable folder.
2. Run the ZALiA executable.

The game folder is portable and does not require an installer. Configuration, saves, and the validated ROM copy use ZALiA's Windows save area, normally `%LOCALAPPDATA%\ZALiA`.

## Select a Zelda II ROM

On first launch, ZALiA opens a file picker for a Zelda II `.nes` file.

Supported SHA-1 checksums:

| Format | Size | SHA-1 |
|---|---:|---|
| Headered iNES | 262,160 bytes | `353489a57f24a429572e76bd455bc51d821f7036` |
| Headerless | 262,144 bytes | `11333adb723a5975e0ecca3aee8f4747aa8d2d26` |

Invalid files are rejected and the picker opens again. Cancelling closes the game. After validation, ZALiA stores a local copy as `zelda2.nes` in its save area so later launches do not prompt again.

The ROM is not included with either the game or the APWorld.

## Configure the Connection

After ROM validation, the first launch creates:

`%LOCALAPPDATA%\ZALiA\ap_config.ini`

The initial connection will fail because the file starts with defaults that will not connect. Close the game if necessary, then edit the ap_config.ini file:

```ini
[Connection]
server=archipelago.gg:38281
slot=Player Name
password=
```

- Replace `server` with the room hostname and port.
- Replace `slot` with the player slot name.
- Set `password` only when the room requires one.

Save the file and relaunch ZALiA. The game reads this configuration and connects automatically at startup.

## Start Playing

1. Create a new save from the file-select screen.
2. The server's slot data configures everything automatically.

The client sends checks directly to the server, receives all item-handling categories, scouts the slot's created locations, and restores server-confirmed checks after reconnecting.

## Updating

- Replace the extracted game files. `%LOCALAPPDATA%\ZALiA` remains intact.
- Multiworld generators should replace the old `zalia.apworld` before creating new rooms.
- Do not reuse a slot generated by an unsupported older APWorld with a newer client.

## Troubleshooting

| Problem | Fix |
|---|---|
| ROM picker appears every launch | Select a ROM with one of the supported SHA-1 checksums and ensure `%LOCALAPPDATA%\ZALiA` is writable. |
| `ap_config.ini` is missing | Complete ROM validation first, then check `%LOCALAPPDATA%\ZALiA`. |
| Initial connection fails and the game closes | Edit `ap_config.ini`, verify the room host and port, then relaunch. |
| Slot connection is refused | Check the exact slot name and room password. |
| The client reports an unsupported old APWorld | Install the current `zalia.apworld` and generate a new multiworld or downgrade the client. |
| Config changes are ignored | Save `ap_config.ini`, close ZALiA fully, and relaunch it. |
